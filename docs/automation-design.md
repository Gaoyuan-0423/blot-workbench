# 批量自动 WB 工作流与可选视觉 API

实施状态 / Implementation status (`0.3.0-dev.1`): 本机共享泳道说明、批量像素候选、手动修改、局部背景定量及描述性图已进入 `#real` 实验预览；视觉 API 实验图分析与复杂样本模型仍未接入。 / Shared lane descriptions, local batch proposals, manual edits, local-background measurements, and descriptive plots are available experimentally at `#real`. Vision-API analysis of experimental images and complex sample models are not implemented. See [guide](real-images.en.md).

需求更新：2026-10-11。本文是下一版的产品与技术设计，不是当前在线 `0.1.0-alpha.1` 的已实现功能说明。

用户希望将全部图像一次导入，以文件名提供蛋白名，再说明泳道对应样本，由程序自动处理并输出图；同时保留完整手动模式。用户已选择允许图片发送给指定的视觉 API。具体服务和模型尚未指定，不进行真实云端调用。

## 默认使用流程

1. **批量拖入 TIFF/PNG。** 原文件保留，计算内容哈希；展示文件名、蛋白名、尺寸、原始位深、可用状态。同名文件不能互相覆盖。以文件名作为用户提供的蛋白标签，保留完整原文件名；不根据蛋白名推断膜、曝光或独立实验重复。
2. **一次说明泳道。** 例如：“这一批都是同一块膜，从左到右是 Ctrl-1、Ctrl-2、Ctrl-3、Drug-1、Drug-2、Drug-3；GAPDH 是内参；这六个样本是六个独立生物学重复。”同一布局批量应用，例外图可覆盖。若只写“前三个对照，后三个处理”，只能得到组别，不能推断独立重复身份。
3. **核对一张汇总表。** 列出文件→蛋白→膜/批次→曝光→泳道→样本→内参关系。不明确的条目集中补充，保存为下次可复用的实验模板。无需每张图重填同一内容。
4. **一键处理。** 视觉 API 返回条带与泳道的候选位置和标签；本地算法校正候选、建议背景、检查条件、读取原始像素并计算。具备明确实验映射、有效 ROI/背景/内参和可用图像的项目自动生成结果草稿；失败项目保留原始输入及原因，进入同一待处理列表，不阻塞其他图片。
5. **查看并导出。** 一屏查看所有图片的取样叠图和输出草稿，一次确认通过的项目；只打开有问题或希望调整的图。任何自动处理结果均可进入手动模式，手动修改后本地重算并更新结果版本。

第一次使用的映射确认和最终结果复核不应被写成“AI 已验证科研正确性”。后续同结构实验复用模板，仍检查新图的泳道数量、尺寸、膜/曝光关系和异常。

## 自动模式与手动模式

两种模式操作同一个项目和同一套 ROI/计算数据，不产生两套不一致的分析文件。

- 自动模式负责批量编排、候选框、背景建议、模板应用、符合明确规则的配对和出图。
- 手动模式支持框选/移动/缩放条带与背景、补漏带、改样本标签、选内参、选择曝光、排除、撤销与重做。
- 人工改过的框和配对默认锁定，不被后台识别覆盖。重新识别时明确选择范围，保留旧参数及结果。
- 图片内容不变时可复用识别记录。ROI 编辑、改颜色及本地重算不反复调用 API；请求缓存同时绑定输入哈希、预览转换、服务、模型与提示词版本。
- 任务提供进度、暂停/取消、单项重试和恢复。重试只针对失败项；没有 API 时仍可完成手动流程。

## API 与本地计算的分工

| 工作 | 执行位置与约束 |
| --- | --- |
| 理解泳道文字、建议结构化样本关系 | API；仅使用用户明确提供的信息，缺失信息返回待填写 |
| 定位条带、读取图片中标签 | 可选视觉 API；输出候选矩形、标签和不确定项，不输出灰度测量值 |
| 解析文件、读取原始位深、原始像素积分 | 本机可测试的解码与计算核心 |
| 扣背景、明确内参配对后的归一化 | 本机确定性算法，保留中间量和方法版本 |
| 原图取样叠图、条带展示图、定量图与表格 | 本机根据保存的真实图像与结果渲染，不使用生成式图片模型绘制实验条带 |

视觉模型可能在精确定位和计数上出错，不能将其回答当作条带积分或科研结论。参见 [OpenAI 视觉能力与局限](https://developers.openai.com/api/docs/guides/images-vision)。这只是相关供应商的能力说明，不代表已经选定或验证某个模型。

API 返回值必须通过严格 schema、坐标范围、泳道数量与用户映射校验。图片、文件名、模型响应均作为数据，不能执行其携带的指令。模型自报的置信度不等同于通过本地质量检查。

## 图像、配对与结果边界

- TIFF/PNG 原始位深和编码子集需逐项验证。浏览器 Canvas 的显示像素不能替代高位深原始数据。多页 TIFF 不静默取首页；不支持的格式明确拒绝或让用户选择页面。
- 发送给 API 的预览可以缩小或转换为 PNG，但必须记录尺寸、显示映射与坐标变换。计算始终回到原始数组，不能对模型服务压缩后的图片定量。
- 同一蛋白可能来自不同膜、日期或曝光。文件名仅为蛋白名时不足以确定这些关系；通过一次批次说明或模板补足，不能自动全部合并。
- 不自动把最亮曝光视为最佳，不把多个曝光平均成新样本，也不直接除以曝光时间作为跨曝光校正。只有条件明确、在验证范围内的曝光才可进入相应分析。
- 多条候选带、样本数不符、不可用背景、缺少内参、非正净信号、疑似超出有效测量范围时，给出原因并请求局部处理，不补造信号或零值。
- 日期、泳道位置和分组编号均不能自动定义独立重复。未明确实验单位时仍可展示逐泳道描述性结果，不生成推断统计、显著性星号或基于错误 n 的误差线。

## 预计输出

1. 全部图片的 ROI/背景叠图，保留原图坐标和人工复核状态。
2. 从真实原图裁剪得到的条带展示图，带蛋白、样本和必要的分隔标记。排版不改变用于测量的像素；不拼成虚假的连续泳道。
3. 按已明确的样本/重复关系生成定量图；默认显示可追溯的数据点。均值、误差线及后续统计需要与实际实验设计匹配。
4. PNG/SVG 图、可复查的 CSV、参数/方法与 API 来源记录、可恢复的项目包。最终支持的 TIFF 图形导出另列验收，不把“可导入 TIFF”冒充“可导出 TIFF”。

结果区分自动草稿、待处理、已人工复核、排除和失效。自动模式可批量生成草稿文件；未解决项不能悄悄进入已复核汇总。导出记录其状态。

## 网页接入与密钥

保持供应商适配层独立，先支持用户配置的一种已验证协议；Base URL、模型 ID 与 API Key 分开设置。兼容协议不等于所有模型均通过验证。不将密钥写入源码、GitHub、前端构建、日志或项目导出；更换服务来源不能自动带走旧密钥。

当前 GitHub Pages 是静态前端，不能承担私密服务端密钥托管。[GitHub 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

部署必须明确选择以下方式，而不是在页面中嵌入共享密钥：

- 本机网页服务管理用户的 API 配置；易于保留本地计算与项目目录，但需要安装/启动。
- 托管网页配独立后端；更接近免安装体验，需要另行确定后端运营、鉴权、用量限制和图片/密钥的数据路径。不能做任意目标地址、无鉴权的公开代理。
- 浏览器直接调用用户配置的服务仅在该服务明确支持浏览器跨域和对应认证方式时考虑；并非所有兼容 API 都能在 GitHub Pages 中直接使用。

用户在批量运行前可看到目的服务、模型、将发送的图片/预览及文字范围。默认只发选定图像的识别预览与必要映射，不发送整个项目或其他文件；不静默切换供应商。具体费用取决于实际服务，不在未选服务时编造价格。

## 当前基础与开发顺序

已发布的 Workbench 仍为合成数据演示。`0.2.0-dev.1` 开发分支先提供可配置视觉 API 与固定合成图连接测试，见[接入指南](vision-api.md)；它还未接入以下真实图像处理流程。连接测试不能证明真实云端模型的定位准确率。

1. 先验证真实 TIFF/PNG 原始数组与人工 ROI 定量，建立合成真值和固定方法对照。
2. 加入批量导入、自然语言泳道映射的结构化确认与模板；手动流程在此阶段即可完成真实任务。
3. 接入可配置视觉 API、原图坐标校正、异常队列和成本/取消控制。对同一参考数据分别比较自动定位误差与固定 ROI 下的计算误差。
4. 加入批量输出与项目恢复；测试同名文件、多膜/曝光、缺失内参、失败重试、手动覆盖保护和原始数据迁移。

不把“每张都产出一个图”作为成功标准。验收同时检查合法任务的完成率、错误配对率、需要人工处理的比例、结果复现、API 数据范围和密钥泄漏，以及相较逐图手工操作的实际节省。

本设计借鉴用户描述的竞品通用批处理流程，不复制竞品代码、素材或具体界面，也不声称已独立验证其自动分析能力。
